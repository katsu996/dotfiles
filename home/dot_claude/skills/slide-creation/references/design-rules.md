# デザイン規約

## 1. 情報密度

高密度とは、文字や図形を大量に詰め込むことではない。次の理解段階が1枚の中で接続されている状態を高密度と定義する。

1. 何が起きているか
2. なぜ起きているか
3. どのような仕組みで影響するか
4. 結果として何が起きるか
5. 読み手にとって何が重要か

- 入力に原因・背景・条件・具体例・例外・対応策が含まれている場合、短い名詞だけに圧縮せず、1〜3行の説明や箇条書きとして残す。
- 入力に情報がない場合は、一般論や推測で空白を埋めない。代わりに図の大きさ、文字サイズ、列幅、余白、領域配分を調整する。

## 2. 文字の階層

フォントはすべて **Noto Sans JP** に統一する。

文字サイズ・太さ・位置・余白で、最低でも次の階層を明確に区別する。

スライドタイトル / リード文 / 主要領域の見出し / 項目見出し / 本文・箇条書き / 注記・出典

- 親見出しは直下の本文より明確に大きくし、太さも一段強くする。
- 同じ階層の情報は、同じサイズ・太さ・色・字下げで統一する。
- 説明セクションでは「親見出し → 同列の内訳・箇条書き → 解釈・補足」の3段階を表現する。すべてを同じ大きさ・同じ太さにしない。
- 文字を小さくして無理に収める前に、重複表現の削除、短文化、列幅の変更、領域の再配分を行う。

## 3. 箇条書きとグルーピング

同じ親に属する複数項目は、原則として箇条書き・表の行・整列したラベルのいずれかでまとめる。

- 親見出しと子項目を同じ階層にしない
- 箇条書きは一項目一論点
- 同列項目の文法と粒度をそろえる
- 原因・具体例・結果を同じリストへ混在させない
- 入れ子は原則2階層まで
- 1項目しかない場合は装飾的な箇条書きにしない

文章として連続して読む必要がある説明や解釈は、無理に箇条書きへ分解せず、短い文章として配置する。

## 4. ボックスと枠線

文章を置くためだけに、角丸カードや枠付きボックスを大量に使用しない。閉じた枠を使ってよいのは次に限る。

- システム境界や責任範囲を示す
- 包含関係そのものに意味がある
- 独立した工程や比較対象を示す
- 例外・警告・重要リスクを明確に分離する
- 背景色や境界が分類・状態を表す

それ以外は次の順番でグルーピングする。

1. 余白
2. 整列
3. 文字サイズと太さ
4. 箇条書き・番号
5. 細い区切り線
6. ごく薄い背景面
7. 必要な場合だけ閉じた枠線

- 角丸、影、グラデーション、装飾目的のカード、二重線は原則として使用しない。
- 同じ説明領域に3つ以上の閉じたカードを縦に並べる「カードの壁」を作らない。

## 5. 配色

基本配色は、1つの青系統と白・グレーで統一する。

| 用途 | HEX |
|---|---|
| 白背景 | `#FFFFFF` |
| 濃紺 | `#12385B` |
| 青 | `#1779BA` |
| 水色 | `#DCEEF7` |
| 薄い水色 | `#EEF5F9` |
| 本文 | `#182235` |
| 補助本文 | `#607089` |
| 構造線 | `#A9B8C8` |
| 薄い罫線 | `#D5DEE7` |
| 赤アクセント | `#E84A5F` |
| 赤の薄い背景 | `#FCE8EC` |

配色ルール:

- ページの大部分を青・白・グレーで構成する
- 赤は重要なリスク、警告、負の差分、例外だけに使う
- 赤を定型的に使用しない
- 緑・黄・オレンジ・紫は、ブランド指定がない限り使用しない
- カテゴリーの違いを多色で表現しない
- 色を外しても構造が分かるようにする
- 右上に意味のない赤枠を定型配置しない

## 6. 矢印・矢羽根・接続線

矢印は、因果・引継ぎ・入力出力・移動を示す場合だけ使用する。

時間軸・フェーズ・ロードマップ・成熟段階には、通常の矢印ではなく原則として **矢羽根** を使用する。矢羽根の標準形は、左端が直線で右端だけが尖る形。

- フェーズごとに1つの矢羽根を使用する
- 矢羽根同士を重ねない
- 高さとベースラインをそろえる
- 年次やフェーズ名は矢羽根内に直接配置する
- マイルストーンや目標は対応する矢羽根の近くへ置く
- 下段の実行ステップも、左から右へ進む場合は矢羽根または共通時間軸を使う
- 静的な分類には矢羽根を使わない
- 接続線は文字や図形と衝突させない
- 線が多い場合は、個別線ではなく共通バスや番号対応を使う

## 7. グラフ・表・数値図

グラフや表だけを大きく置いて終わらせない。入力に原因・背景・メカニズム・例外・含意がある場合は、主図と組み合わせて配置する。

説明領域は、グラフの数値を文章で繰り返すのではなく、主図だけでは分からない次を補完する。

- なぜ変化したか
- どの要因が大きいか
- どの条件が影響したか
- 何が相殺・増幅したか
- どのような経営上の意味があるか

主図と説明の対応が必要な場合は、同じ番号・色・順序・見出し・近接配置で対応させる。

## 8. 共通フレーム

複数枚を作る場合は、全ページで次の位置を統一する。

ヘッダー / タイトル / ページ番号 / リード文 / 本文領域 / フッター区切り線 / 出典 / 右下ラベル

- 本文量によって、タイトル・リード文・フッターの位置を動かさない。
- 情報が収まらない場合は、本文内の領域配分、文章量、構造、ページ分割を見直す。

具体的な座標は `pptx-implementation.md` の共通フレーム表を使う。

## 9. 改行と文字収まり

- 固有名詞の途中で改行しない
- 数値と単位を分断しない
- 2行目に数文字だけ残る改行を作らない
- タイトルは原則1行
- 見出しは最大2行まで
- 重要本文を極端に小さくしない
- 文字を縮小する前に、文章とレイアウトを見直す
- 図形内の上下余白と垂直中央をそろえる
- 表や図形から文字をはみ出させない

## 10. 出典と情報の正確性

スライド下部に、使用した資料名・対象セクション・ページ・基準日などを可能な範囲で記載する。

- 原文の数値・単位を維持する
- 判断時点を維持する
- 非網羅性や対象外条件を落とさない
- 分析上の分類を公式分類のように見せない
- 入力にない情報を補わない
- 不明な内容は「未確認」「要検証」「前提」として扱う
