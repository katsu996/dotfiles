# 図解構造とレイアウトの選択

## 1. 図解構造の候補

最初から表・フロー・カードに決め打ちせず、内容に適した構造候補を内部で2〜3案比較する。

1. 高密度表・マトリクス
2. 業務フロー・プロセス
3. スイムレーン
4. 因果チェーン
5. ドライバーツリー
6. 現状／将来比較
7. システム構成図・レイヤー
8. ロードマップ・時間軸
9. 循環・学習ループ
10. 数値ブリッジ・ウォーターフォール
11. リスク・ランドスケープ
12. 多数要素から共通要因・共通影響への集約構造
13. ネットワーク・エコシステム
14. グラフや表と原因・背景・示唆を組み合わせた複合構造

### 比較の観点

- 入力内容との適合度
- 因果、順序、比較、包含関係の正確さ
- 読み手の判断への有用性
- 情報密度と読みやすさ
- ページ全体のストーリーのつながり
- PowerPoint上での編集しやすさ
- 入力にない関係を作ってしまう危険性

### 守るべき制約

- 明示的な順序がない場合、フローにしない
- 因果が確認できない場合、因果図にしない
- 発生確率や影響度がない場合、リスクヒートマップを作らない
- 関係のある情報を、独立したカードの羅列にしない
- 共通の比較軸がない情報を、無理に表へ押し込まない
- 主図だけでは「なぜ」「だから何」が分からない場合、背景・原因・含意をボディ内に統合する
- 情報の関係を一つの型だけで表せない場合、主構造と補助構造を組み合わせる

## 2. 複合構造の設計

1枚を単純な表や単一の図だけで終わらせない。必要に応じて次のような複合構造を使う。

- 数値ブリッジ＋増減要因の説明
- ロードマップ＋実行管理レーン
- 複数グラフ＋対応する経営示唆
- 目指す価値＋中核構造＋実装基盤＋学習ループ
- リスク分類＋失われる対応能力＋共通影響への収斂
- システム境界＋利用主体＋接続関係＋運用・例外
- 比較表＋重要な差分の解釈
- 業務フロー＋責任主体＋例外・差戻し

複数領域を並べる場合は、置くだけで終わらせず、次のいずれかで関係を明示する。

矢印・接続線 / 共通軸 / 対応する番号 / 同じ順序 / 共通バス / 近接配置 / 色の役割 / 列・行の対応 / 集約点・分岐点

**「なぜこの2つの領域を同じページに置くのか」を一文で説明できない場合は、構造を再設計する。**

## 3. レイアウト候補の比較

図解パターンを選んだ後、同じ情報を配置するレイアウト候補を内部で3案比較する。

- 左右分割
- 上下分割
- 全幅の主図＋直接注釈
- 複数の小図を並べるスモールマルチプル
- 中央主図＋周辺説明
- 全幅主図＋短い補足領域
- 時間軸＋複数の実行レーン

左右を反転しただけ、色を変えただけ、列幅を少し変えただけの案は別案として扱わない。

「左に図、右に文章」を既定値にせず、次の観点で最適な配置を選ぶ。

- 主図に必要な幅と高さ
- 読み順の自然さ
- 関連する事実と説明の距離
- 情報密度のバランス
- 空白の偏り
- 親子関係・因果関係の見えやすさ
- 編集のしやすさ

候補比較や採点結果はスライド上に表示せず、内部でのみ使用する。
