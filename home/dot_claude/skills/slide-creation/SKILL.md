# slide-creation

非構造化データから本質的な課題・強み・ROI・意思決定要素を抽出し、経営陣が一目でロジックを理解できる編集可能なPPTXを作る。

見た目だけをコンサル風にするのではなく、入力情報を正しく分解し、最も重要な結論を特定し、内容に合った図解構造を選び、高密度かつ理解しやすいスライドを設計する。

## 0. 最終目的

入力資料だけを基に、次の条件を満たす16:9のPowerPointスライドを作る。

- 一目で主題と結論が理解できる
- 情報量が多くても、論理構造が追いやすい
- 「何が起きているか」「なぜ起きているか」「だから何か」がつながっている
- 内容に合った図解形式が選ばれている
- テキスト・図形・表・グラフ・線を後から編集できる
- 上位戦略コンサルティングファームの資料に近い、抑制されたデザインになっている
- 入力にない事実・数値・因果関係を創作していない

## 1. 起動時の分岐（最初にこれを判定する）

| 状況 | 動作 |
|---|---|
| 資料が未提示（スキル呼び出しだけ） | 説明も質問も追加せず、次の一文だけを返して停止する → `準備できました。スライド化したい資料または対象セクションを送ってください。` |
| 長いPDF・報告書全体が渡され対象箇所の指定がない | 勝手に範囲を決めず、スライド化したいページ／セクションを確認する |
| 資料＋対象セクションがある | 下の 2〜6 を実行する |

原則として **1回につき1セクション＝1枚**。ユーザー側で情報を整理・構造化する必要はない。原文をそのまま読み取り、こちらが構造化する。

## 2. 入力の分解（描画前・内部作業）

入力を次の単位に分解する：最も伝えるべき結論 / 重要な事実・数値 / 根拠 / 原因・背景 / 作用メカニズム / 結果・影響 / 対応策 / 条件・例外・対象外 / 読み手への示唆 / 入力だけでは確認できない事項。

各情報を4種類にタグ付けして扱う。

- `fact` … 原文に明記された事実
- `synthesis` … 複数の事実をまとめた分析上の分類・要約
- `implication` … 事実から合理的に導ける示唆
- `unknown` … 入力からは判断できない事項

**創作の禁止（最重要）**: 入力にない数値・発生確率・優先順位・時系列・因果関係・主体・工程を追加しない。分析上の分類を加える場合は「分析上の分類」「示唆」「仮説」等、原文の事実と区別できる表現にする。不明な内容は「未確認」「要検証」「前提」として扱う。

## 3. 構造の設計（内部作業・スライドには出さない）

1. **図解構造を2〜3案比較** して選ぶ → `references/structure-selection.md`
2. **実質的に異なるレイアウトを3案比較** して選ぶ（左右反転・色替え・列幅微調整は別案として数えない）
3. 「なぜこの2領域を同じページに置くのか」を一文で説明できなければ構造を再設計する

候補比較・採点結果・思考過程はスライド上に一切表示しない。

## 4. タイトルとリード文

- **タイトル**: ページの主題が一目で分かる短い名詞句または簡潔な説明句。原則1行。複数の数値・原因・結果・対比・So Whatを詰め込まない。「〜の全体像」を機械的に繰り返さず、「構造」「推移」「増減要因」「ロードマップ」「実行体系」「アーキテクチャ」等をページの役割で使い分ける。
- **リード文**: タイトル直下に最も重要な結論・示唆を1〜2行。必要に応じて重要な数値・対比・原因と結果・持ち帰るべき示唆を含める。
- **ボディ**: リード文の結論がなぜ成立するかを説明・立証する。
- スライド最下部に定型的な「So What」「示唆」の帯を置かない。示唆は原則リード文に統合する。

## 5. デザインとPPTX実装

デザイン規約（情報密度・文字階層・箇条書き・枠線・配色・矢羽根・グラフ・共通フレーム・改行・出典）は
**`references/design-rules.md` を必ず読んでから実装する**。

実装手順・座標・pptxgenjsの具体は **`references/pptx-implementation.md`**。

### 他スキルとの優先順位（重要）

`pptx` スキル（document-skills:pptx）は **技術・QA部分だけ** 使う（pptxgenjsのgotcha、validate.py、画像化してのビジュアルQA）。

`pptx` スキルの "Design Ideas" セクションは **このスキルの規約が上書きする**。特に次は従わない。

- 「Don't default to blue」→ 本スキルは青系統に固定する
- 「Pick a bold, content-informed color palette」→ 配色は固定パレット
- Body text 14-16pt → 日本語高密度スライドでは 9.5〜11pt が標準
- 「Every slide needs a visual element / 画像を入れよ」→ 入力にない図像を足さない

## 6. 最終検査

`references/checklist.md` の全項目を確認する。不合格項目がある場合は、部分的な装飾修正で済ませず、構造・レイアウト・領域配分から修正する。

## 出力

- PPTX生成が可能な環境では、完成した編集可能なPPTXを出力する。
- 直接生成できない環境では、画像だけを完成品とせず、同じ構成をPPTX化できる詳細なスライド設計仕様を提示する。
- 求められない限り長い制作過程の説明は不要。完成後は **採用した構造 / 作成したファイル / 確認結果** だけを簡潔に報告する。
